Claude Navigator: route the task, not the user.

A routing-intelligence concept that helps Claude users choose between Agents, Projects and Prompts by explaining which capability fits their actual task.

01 · Problem

The capability suite was not the problem. Choosing was.

Claude offers multiple capability paths — Agents, Skills, Projects and Prompts. The case study identifies a routing problem: users know what they want to accomplish but do not know which mode will fit the task without wasting time, tokens or effort.

Core insight: Today's tools treat capability selection as a search problem. Navigator treats it as a decision-confidence problem.
88%failed first try or gave up
40%said task-fit confusion was the hardest decision
68%retreated to basic prompts after failure
12%felt fully confident in their choice
02 · Research

Research showed the friction happens at the decision moment.

The primary research surveyed 25 Claude Pro/Team users using behavioural questions about real past tasks. The evidence pointed to decision friction rather than capability awareness.

Selection bottleneck

40%

Did not know whether Agent fit the task.

Trade-off gap

28%

Could not judge cost, quality and speed trade-offs.

Setup wall

16%

Hit configuration difficulty after choosing Agent.

Cost anxiety

12%

Feared wasting tokens on the wrong approach.

Research conclusion: more than 88% of the observed difficulty was in decision-making, not capability access.
03 · Target segment

Design for the “Aware & Frustrated” Capable Explorer.

The target segment already understands AI and actively wants to use advanced capabilities, but repeatedly fails at the capability-selection or setup step.

Persona

Arjun, 29 · Senior Engineer

Uses Claude daily for code review, debugging and research.

Pattern

Clear task → configuration wall

Tries Agent, spirals into trial-and-error and manually re-prompts.

Emotion

Self-doubt, not capability doubt

“I know Claude can do this — why can't I figure this out?”

Need

Signal + scaffold

Wants a clear fit signal and pre-filled path, not more documentation.

04 · Product decision

Choose routing intelligence over more documentation.

Three solution directions were evaluated against the task-fit gap, independence from external dependencies, decision timing, confidence-building and scalability.

Solution 1

Better docs & tooltips · RICE 28

Improves comprehension, but users already know what capabilities do. It does not answer “does this fit my task?”

Solution 2

Community recommendation · RICE 35

Maps to existing behaviour but introduces noise, latency and dependence on other people.

Solution 3 · MVP

Navigator · RICE 160

Starts with the user's actual task, scores capabilities and explains the trade-offs before configuration.

JTBD

Confident first-try capability choice

Translate a complex task into a capability choice the user believes will succeed.

05 · Prototype

Remove the mode selector from the start.

The prototype deliberately starts with the user's task in plain language. Navigator detects complexity, extracts intent dimensions and then presents ranked capabilities with auditable reasoning.

01 · Get started

Describe your task

No mode selector. The user starts where they are: the task they need to complete.

02 · Intent analysis

Five intent dimensions

Task type, complexity, tool needs, repetition flag and branching logic.

03 · Recommendation

Fit score + reasoning

Three ranked capability cards quote the user's own words to explain the fit.

04 · Configuration

Scaffold the next action

Paid-tier concept adds pre-filled Agent / Project / Skill configuration, token estimates and saved templates.

06 · Journey & architecture

North Star

Task-Fit Confidence Uplift

At least 60% of users report confidence ≥4/5 after recommendation.

Activation

Session completion

More than 60% reach a capability pick.

Efficiency

Token efficiency

Target 40% lower token usage versus a no-Navigator baseline.

Guardrail

Generic routing

Keep recommendations reported as arbitrary below 15%.

08 · GTM & risks

Distribution should happen at the moment of uncertainty.

Primary channel

In-product contextual trigger

When complexity crosses the threshold, surface Navigator inline before the user sends the task.

Launch signal

Power-user communities

Seed access to Claude Discord and r/ClaudeAI contributors for high-signal feedback.

Activation

Dormant Pro users

Use specific, data-backed prompts to show where Agents could save time.

Risk

Over-routing to Agents

Recommend Agent only when enough intent signals fire and show cost before execution.

Risk

AI advising AI

Make reasoning auditable: show the task evidence and capability trade-offs.

Risk

Cold-start ambiguity

Ask a clarifying question rather than guessing; default to the safest capability tier.

Product principle: Reasoning beats choice. If Navigator cannot explain why a capability fits the user's own task, it has not solved the problem.
